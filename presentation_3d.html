INTRODUCTION

1.3 - 1.4 Défis & Cibles

La Problématique

  • Fiches de pannes papier perdues ou illisibles.
  • Temps moyen de réparation (MTTR) trop élevé.
  • Accès impossible aux documentations machines sur site.
  • Ruptures et incohérences dans les stocks de pièces.

Les Objectifs

  • Digitalisation intégrale : Flux dématérialisé.
  • Validation sur site : Démarrage validé par scan QR Code.
  • Assistance par TECHBOT : Utilisation d'IA générative RAG.
  • Stocks en direct : Liaison mobile technicien / magasinier.

ANALYSE DES BESOINS

2.1 - 2.2 Solution Globale
1. Mobile Technicien

Application Flutter permettant de recevoir les alertes, scanner les machines, solliciter TECHBOT en cas de panne et déclarer les rapports de travail.

2. API & IA RAG

Serveur FastAPI asynchrone orchestrant la base PostgreSQL, l'indexation vectorielle ChromaDB et l'intégration de Gemini pour les réponses intelligentes.

3. Console Admin/Stock

Interface Desktop Windows pour les chefs d'équipe et magasiniers. Gère les plannings, valide les bons de pièces et suit le MTTR par des indicateurs BI.

3.2 - 3.3 Modélisation

Modèle Utilisateurs

Un compte de base Utilisateur partagé hérite de rôles spécifiques : Technicien, ChefEquipe, Superviseur, Magasinier et Administrateur via des tables SQLAlchemy liées.

Cycle d'une Panne

La Panne est déclarée par un superviseur sur une Machine. Elle engendre une Intervention, qui se conclut par un RapportPanne (bon de travail numérique) et d'éventuelles DemandeRechange de pièces.
